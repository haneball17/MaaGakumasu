# HIF MVP 已确认决策

_最后更新：2026-07-20_

## 范围与验收

1. MVP 仅覆盖 MuMu 12 日文原版的 `rinami_garakuta_road`。
2. 正式验收要求从 HIF 入口单次运行到 `優勝` 结算并回到可控状态。
3. 当前探路局用于补齐后续证据；最终必须另开一局完成无人工拼接验收。
4. 最终任务中使用手工 ADB、调试 runner、人工接管或 `UnknownStop` 均判定失败。
5. 本轮采用可达路径覆盖：必经主链、不可规避随机页面和最终实际经过页面；不穷举全部可选分支。
6. 不要求特定高评价等级或分数，但非优胜结算不能作为完成。

## 实现策略

7. 当前主工作区的最新 HIF 差异是权威基线；旧 `.worktrees/hif-round1` 仅只读参考。
8. 首轮并发资源优先用于状态读取、路线评分器和 Pipeline 审计，Sparse Expectimax 不阻塞 MVP。
9. 首版采用结构化卡牌效果和确定性路线评分器，不硬编码当前局出牌序列。
10. 状态真值采用“当前观测 + 同一局已验证账本”，禁止默认值、历史样本和过期 Session 补值。
11. Round1 与 Round2 分别达到独立 `8+2` 后才能开放有界循环。
12. 历史视频可用于离线分类，但状态改变 Action 必须取得当前探路局的实机证据。
13. 决策核心使用独立日志与 Schema，通过领域标识符关联 `HIFJournal`。

## 并发与版本控制

14. 主 agent 独占 Pipeline、实机 Action、runner、Session、主路由测试和任务文档。
15. 状态、评分器和审计 agent 使用独立 worktree 与严格文件所有权，禁止跨范围顺手修改。
16. 子 agent 形成小提交，由主 agent 审查后择取；不整体合并旧 worktree。
17. 允许创建本地分支、worktree 和中文 Conventional Commits；未经再次确认不 push、不建 PR、不发布。
18. 子 agent 工具不支持指定 `gpt-5.6-terra / high`；接受平台分配模型，并在任务提示中要求高深度分析和严格验证。

## 资源与自治

19. 允许启动一次最终验收局，消耗正常入场体力、票券或免费次数，并使用局内资源与免费重试。
20. 允许在已确认边界内自主采证、修复、测试、受限点击和通信错误恢复，无需逐页请示。
21. 始终禁止付费、账号操作、猜测输入、主动放弃后反复开局及未经确认的外部发布操作。

## 上下文持久化

22. 本任务新增文档统一放在 `plans/hif-mvp/`。
23. 每个里程碑必须先验证，再更新并提交 `STATUS.md`；涉及实机证据时同步更新 `HANDOFF.md`。
24. 既有根计划、旧 handoff 和决策专项文档保留为历史资料，不移动或覆盖。

## Pipeline 专项技能

25. Pipeline 文档与实现必须按任务使用 `pipeline-guide`、`pipeline-generate`、`pipeline-option` 和
    `pipeline-testing`。
26. 技能中的外部项目路径和节点示例不能直接复制；仓库结构、现有节点和 `AGENTS.md` 优先。
27. 跨页面有限状态优先用 `next + [JumpBack]`，OCR 先做实帧与 ROI sweep，选项优先 pure override。
28. 单文件节点测试不能代替跨文件全 bundle 集成测试；测试期间继续遵守本任务资源与实机安全边界。

## Day1 场景3变卡

29. 变卡首版只接入 `TEST_HIF_day1.json` 的 Day1 场景3；取得页面证据和测试闭环前，不接入正式 `ProduceHIF.json`。
30. 固定顺序为：候选页完整浏览牌库并返回、扫描三个候选与再抽次数、一次决策、选择候选、重新定位来源实例、提交“チェンジ”、结果 OCR 验证后停留。
31. 卡牌以日文名和详情映射 `card_id`；未知卡允许存在但绝不被选择。相同 `card_id + 强化状态` 的重复来源卡可互换。
32. 决策只有 `preferred_select`、`forced_fallback`、`blocked`；不存在跳过变卡。存在可识别组合时，测试模式提交最小损失 fallback。
33. 再抽次数仅供决策读取，不自动点击再抽。用户手动再抽后只重扫候选、保留牌库快照并重新决策。
34. 每个 session 保存 `debug/hif-snapshots/<session_id>.json`，恢复必须显式指定 session 并重新验证当前页面；Journal 与 Maa 日志提供全部可追溯事件和前后帧。
35. 实施前必须补齐牌库入口、牌库底部、关闭回候选、变卡结果四类实机证据；未采证页面、坐标、ROI 或后态一律安全停止。
