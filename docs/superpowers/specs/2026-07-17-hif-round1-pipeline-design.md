# HIF 到 Round1 管线设计

## 目标

在 MuMu 12、日文原版、`720x1280` 环境中，从“开始培育”选择 HIF，安全经过本战准备剩余 `6` 至 `1` 日的所有已记录页面，到达 Round1 后只读识别并停止。

## 范围

- 覆盖 [finals-daily-log.md](../../hif/finals-daily-log.md) 中已获证的授业、公开课、差し入れ、饮料/技能卡奖励、饮料溢出、`セレクトチェンジ`、咨询、排名转场和 Round1 页面。
- 中途恢复只接受同时命中“`H.I.F本戦まで`”与剩余日数的窄锚点。
- 未采样的随机分支、DMM、汉化及非 `720x1280` 环境不在本期范围；均安全停止。
- Round1 是终点：不选卡、不出牌、不进入 Interval/Round2。

## 架构

继续使用现有 `ProduceHIF.json + agent/custom/action/produce_hif.py` 混合状态机，不新建外部编排器：

```text
Produce
  -> HIF 入口/准备/开始确认
  -> ProduceEntryHIF（唯一页面根路由）
  -> remaining_day=6..1 的已知页面动作
  -> finals_ranking_transition
  -> Round1 观察
  -> StopTask
```

每个状态改变都遵守：`唯一页面识别 -> 唯一配置目标 -> 一次输入 -> 已知后态验证 -> 回根路由`。目标不可见、候选不唯一、截图/后态缺失或任何未知页面都进入 `ProduceHIFUnknownStop`；不得按“次优”候选回退。

## 玩家配置

不使用外置 JSON，也不接入自动决策模块。通过 MaaFramework 任务界面的原生 `select` 选项声明每个已知不可逆页的目标：课程、奖励、变卡和咨询行为。

- 复用现有 `HIF预设`、`HIF执行模式` 和 `HIF Day1课程`。
- 新增选项只覆盖日志中已有证据的页面；内部 `custom_action_param` 使用蛇形命名。
- 公开课识别继续通过原生 `HIFPublicLessonPreviewDetail` 输出基础属性、体力和星等 `detail`；本期只验证玩家指定的课程，不据此自动择优。
- 默认模式仍为观察；单步执行模式下每次任务最多允许一项不可逆输入。

## 测试与实机验收

每项生产改动先写失败测试，再做最小实现。离线验证覆盖：

- 页面锚点、配置注入、路由顺序和未知页停止；
- 唯一目标、一次点击、预期后态和错误后态停止；
- 每个已记录页面的识别 fixture；
- 排名只接受 Round1 后态，以及 Round1 的零输入停止。

实机验证从用户手动恢复或新开的 HIF 入口开始。每次任务最多输入一次，保存 `before`/`after`、MaaFramework 日志和 Journal；实际经过的完整路线到达 Round1 后停止。调试证据只保留在 `debug/`，不纳入版本库。

## 非目标

- 自动课程评分、属性上限/试镜线、P-item 策略和长期决策模块；这些仅保留为后续经验。
- 未经证实页面的自动推进或固定延迟绕过。
- Round1 自动出牌及其后的流程。

## 验收条件

1. 所有日志中已记录的页面都有对应离线识别和安全行为测试。
2. 从干净 HIF 入口的实机单步链路可在已配置路线内推进；任一异常均无额外点击地停止并留下证据。
3. 排名转场后唯一确认 Round1，随后 `StopTask`；控制器日志中没有 Round1 输入。
