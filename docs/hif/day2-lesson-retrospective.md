## 已修正的认识

### 不固定选择某门课程

最初的 `TEST_HIF_2.json` 使用固定 Vo 课程，只用于验证“场景 A -> 点击 -> 场景 B”的标准管线链路。它不能代表正式课程策略：当前候选可能没有 SP 标记，课程收益也会随候选变化。

正式流程不应按课程名称或老师建议选择，而应读取当前候选的实际预览收益后再决定。

### 不用 SP 标记推断收益

SP 是 P-item 条件可能依赖的课程状态，但课程基础收益以选中后的预览浮层为准：星星及各属性图标上方的 `+N` 即为当前候选的基础增量；未显示 `+N` 的属性按 `0` 记录。

### 2026-07-26 预览样本

- Vo 公开课预览：体力 `-8`、星星 `+30`、Vo `+120`、Da `+20`、Vi `+0`。
- Da 公开课预览：体力 `-8`、星星 `+30`、Vo `+20`、Da `+120`、Vi `+0`。

这与较早样本的副属性不同，说明同名公开课的预览收益应逐次读取，不得按历史样本或 SP 标记推断。

## 标准状态链路

当前主线仅保留并完善安全的页面识别、课程预览采集与单次验证能力：

```text
hif_lesson_scene_flag
-> hif_lesson_preview_collect
-> hif_lesson_result_flag
-> stop
```

约束：预览采集必须确认“切换候选只改变预览、不会结算课程”。若该前提在实机上不成立，采集流程必须停止，不能为了收集三个候选而连续点击。

MaaFramework 的等待语义也应保持明确：等待场景 B 的 `timeout` 写在触发动作的节点；未知页面走 `on_error`，不能放进 `next`。否则 `DirectHit` 兜底节点会抢先命中，导致无法等待目标场景。

## 后续经验：自动课程决策（不纳入当前主线）


### 评分约束

1. 每项能力值上限为 `3200`。溢出部分不计入有效收益：

    ```text
    effective_gain = max(0, min(3200, current + predicted_gain) - current)
    ```

2. 试镜能力基准由玩家局外配置，按“角色 + 剧本 + Round”保存，允许 Vo、Da、Vi、星星分别配置。相同角色在相同剧本中的基准线应复用配置，不能每局临时猜测。
3. 必须考虑后续可保证的课程、训练或事件收益。未知随机机会按 `0`，避免因乐观预支导致试镜能力不达标。
4. SP 课程仅用于触发适用的 P-item 规则，不是绝对优先级。
5. P-item 追加收益是否也吃属性百分比加成，必须以结果页实际增量校准，未验证前不作假设。
6. 老师建议不进入采集、评分或同分决策。

建议的优先级为：

```text
试镜目标缺口且后续无法保证补齐
> 3200 上限截断后的有效收益
> 满足条件的 P-item 追加收益
> 星星收益
> 体力成本
```
