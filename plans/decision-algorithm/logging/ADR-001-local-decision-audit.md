# ADR-001：本地决策审计架构

- 状态：已确认
- 日期：2026-07-15
- 范围：`rinami_garakuta_road` HIF Round1/Round2 决策算法

## 背景

现有 `HIFJournal` 能追加 JSONL 和保存帧证据，但事件主体主要是自由文本，缺少稳定领域 ID、决策生命周期、版本化 Schema、搜索复算信息、
跨进程恢复与容量管理；写入异常会被静默忽略，帧审计也只判断像素是否变化，不能证明游戏语义后验成立。

本项目目前仅考虑本地使用，因此目标是让开发者能够回答“算法看到了什么、比较了什么、为什么选中、实际点了什么、结果是否符合预期”，
而不是抵抗拥有本机完全权限的恶意攻击者。

## 决策

1. 采用 `audit`、`decision`、`diagnostic`、`evidence` 四层本地文件日志，并用统一领域 ID 和 trace/span ID 关联。
2. 审计关键事件采用 fail-closed：事件及其必需证据未成功持久化时，控制器不得执行输入。诊断日志采用 fail-open，但必须产生可见降级事件。
3. 用强制版本化 Schema 和稳定原因码替代自由文本事件契约。
4. 动作采用 `observed → normalized → planned → approved → intended → executed → verified` 生命周期，语义后验取代“画面发生变化”的弱验证。
5. 保存原始识别状态、实际算法状态、状态差异、根候选统计和按风险触发的逐情景明细，以支持确定性离线复算。
6. 仅实现本地可靠性：递增序号、完整行追加、关键刷新、末尾残行隔离、证据 SHA-256 和跨 session 分段关联。
7. 不对游戏相关数据脱敏，但只允许字段白名单，禁止采集系统凭据、令牌和无关秘密。
8. 使用分级保留和容量上限，提供轻量查询/校验/重放/报告 CLI，不引入数据库和远端可观测性服务。

## 明确不采用

- 不采用事件哈希链、数字签名、WORM 存储或远端日志服务；这些能力对当前本地威胁模型过重。
- 不要求完整保存每个深层搜索节点；默认保存根候选完整摘要，并在关键或异常决策中扩展逐情景明细。
- 不把 `session_id` 当成业务运行 ID；重启恢复时 `run_id` 可延续，而 `session_id` 必须更新。
- 不允许普通日志库直接吞掉审计写入异常，也不允许先点击后异步补写关键事件。

## 后果

- 好处：每次点击都有输入状态、算法解释、审批、执行和语义结果的连续证据；同一决策可离线复算；日志故障不会产生无记录点击。
- 成本：关键路径增加 Schema 校验和同步刷新；截图与情景明细增加磁盘占用；事件契约、代码、测试夹具和文档必须同步维护。
- 缓解：大对象独立存储并按需触发，运行结束压缩；设置分级保留上限；性能门槛明确计入日志开销。

## 依据

- [OpenTelemetry Logs Data Model](https://opentelemetry.io/docs/specs/otel/logs/data-model/) 提供事件时间、观察时间、严重级别、资源、组件和 trace/span 关联的统一模型。
- [W3C Trace Context](https://www.w3.org/TR/trace-context/) 定义 32 hex `trace-id`、16 hex 父操作 ID 及跨组件传播原则。
- [OWASP Logging Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html) 建议使用交互标识关联事件、区分审计与诊断用途、测试日志故障并限制磁盘消耗。

这些资料用于字段与可靠性原则，不代表首版必须部署 OpenTelemetry 或安全日志平台。
