# HIF 决策日志术语表

| 术语                 | 定义                                     | 生命周期/边界                                    |
| -------------------- | ---------------------------------------- | ------------------------------------------------ |
| Run                  | 一次完整 HIF 培育业务运行                | 进程重启后经状态验证可以延续                     |
| Session              | 一次程序进程会话                         | 每次启动重新创建                                 |
| Round                | HIF Round1 或 Round2                     | 属于一个 Run                                     |
| Turn                 | 一次需要重新观察并选择动作的出牌阶段     | 状态变化并进入下一次选择时结束                   |
| Decision             | 对一个确定的规范化状态执行的一次规划     | 状态、配置或搜索重新开始时创建新的 `decision_id` |
| Action attempt       | 一次具体动作执行尝试                     | 每次点击或重试都有独立 ID；不能复用旧尝试 ID     |
| Event                | 日志中的最小结构化事实                   | 具有唯一 ID 和递增序号                           |
| Trace                | 一个 Run 的端到端关联上下文              | `trace_id` 在 Run 内保持不变                     |
| Span                 | 搜索、审批、执行、验证等有父子关系的操作 | 使用 `span_id` 和 `parent_span_id` 关联          |
| Audit log            | 决策与执行的最小事实主线                 | 关键写入失败时必须停止                           |
| Decision log         | 搜索候选、风险、采样和评分细节           | 根候选摘要属于关键记录                           |
| Diagnostic log       | 识别、性能和组件调试信息                 | 可以降级，但必须告警                             |
| Evidence             | 截图、状态和情景明细等大对象             | 由相对路径、类型、大小和 SHA-256 引用            |
| Observed state       | 识别器看到的原始结果                     | 可包含候选值和置信度，不直接等于算法输入         |
| Normalized state     | 通过不变量校验后实际送入算法的唯一状态   | 其稳定哈希绑定一次 Decision                      |
| State diff           | 两个已定义状态之间的字段级变化           | 必须说明变化原因                                 |
| Intended             | 关键日志已提交，系统声明将发送某个输入   | 只有此阶段成功后才能点击                         |
| Executed             | 控制器已尝试发送输入                     | 不代表游戏已接受或状态正确变化                   |
| Verified             | 动作后状态满足预期语义断言               | 不能仅以画面像素变化判定                         |
| Fail-closed          | 关键审计失败时禁止继续危险动作           | 适用于决策、意图、执行和验证主线                 |
| Fail-open            | 非关键诊断失败时主流程可继续             | 必须记录降级并告警                               |
| Deterministic replay | 用已存状态、版本、配置和种子离线复算     | 候选顺序、评分和动作必须一致，耗时可以不同       |
| Protected run        | 当前、未审查或用户锁定的运行             | 不得被自动保留策略清理                           |
